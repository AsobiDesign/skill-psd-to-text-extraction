# psd-to-text-extraction

PSD（Photoshopデザインカンプ）から**テキストだけ**を抜き出す [Claude Code](https://claude.com/claude-code) スキル。

デザインカンプの文字は画像ではなくテキストレイヤーとして入っている。目で読み取って
打ち直す必要はなく、実文字列をそのまま取り出せる。誤字の混入もコピペ漏れも起きない。

- 原稿の書き起こし、文言の一覧化
- コピーの校正、翻訳や外注に渡すテキストの作成
- CMS・ECへの文言流し込み
- 改修前後の文言差分の確認

HTML/CSSを実装してページを作るのが目的なら、[skill-psd-to-html](https://github.com/AsobiDesign/skill-psd-to-html) を使う。

## 出力

1回の実行で2種類できる。

| ファイル | 中身 | 向いている用途 |
|---|---|---|
| `<名前>-text.txt` | 読み順に文字列を並べただけ | 原稿として渡す、校正、翻訳依頼、文言のdiff |
| `<名前>-text.html` | 見出し・リスト・表に整えたもの | 構造の確認、CMSへの下書き、クライアント共有 |

## 依存

`psd-tools>=1.17` だけ。

```bash
pip install "psd-tools>=1.17"
```

ImageMagickもPhotoshopも要らない。外部コマンドを呼ばないので、WindowsでもmacOSでも
同じ手順で動く。

1.10系は新しいPhotoshopが書いたPSDを読めずエラーになる（`Invalid version 8`）。
`AssertionError` が出たらまずバージョンを疑う。

## インストール

### Claude Code のスキルとして使う

全プロジェクトで使えるようにする場合:

```bash
git clone https://github.com/AsobiDesign/skill-psd-to-text-extraction.git \
  ~/.claude/skills/psd-to-text-extraction
```

特定のプロジェクトだけで使う場合:

```bash
git clone https://github.com/AsobiDesign/skill-psd-to-text-extraction.git \
  <プロジェクト>/.claude/skills/psd-to-text-extraction
```

導入後は「このPSDのテキストを抜いて」「原稿に起こして」と頼めば、Claudeが自動で
このスキルを使う。スクリプトの呼び方を覚える必要はない。

### コマンドとして単体で使う

Claude Code なしでも、スクリプト単体で動く。

```bash
git clone https://github.com/AsobiDesign/skill-psd-to-text-extraction.git
cd skill-psd-to-text-extraction
pip install "psd-tools>=1.17"
python scripts/psd_text.py design.psd -o out/
```

## 使い方

```bash
# 2種類まとめて書き出す（通常はこれ）
python scripts/psd_text.py design.psd -o out/

# 画面を絞る／標準出力で確認する
python scripts/psd_text.py design.psd --screen SP_top --txt

# 全体の量だけ先に把握する
python scripts/psd_text.py design.psd
```

| オプション | 意味 |
|---|---|
| `-o`, `--outdir` | 羅列版とHTML版を書き出すディレクトリ |
| `--txt` | 羅列版を標準出力へ |
| `--html` | HTML版を標準出力へ |
| `--screen` | 画面名で絞り込む（部分一致） |

引数なしで実行すると、画面ごとの件数だけが出る。

```
detect   : artboard
  [pc    ] PC_top       1920x4242  テキスト 87件（うち非表示 6）  セクション 9
  [sp    ] SP_top        390x5120  テキスト 84件（うち非表示 8）  セクション 9
```

## 出力の中身

### 羅列版（.txt）

画面 → セクション（PSDの最上位グループ名）→ 読み順、で並ぶ。装飾情報は付かないので、
そのままテキスト原稿として使える。

```
============================================================
PC_top  (pc / 1920x4242)
============================================================

--- news ---
news
2022.12.20
サービス
【プレスリリース】新サービス「サンプルサービス」をリリース！
```

### HTML整形版（.html）

座標と文字サイズから役割を推定してタグを当てる。

- **表** — 2列以上の行が2行以上続き、列の左端が揃っていれば `<table>`。カンプに罫線が
  引かれていなくても、座標が揃っていれば人は表として読むので、座標だけで判断する。
  お知らせ一覧や料金表がここに入る。
- **見出し** — その画面で最も多く使われている文字サイズを本文とみなし、それより
  大きいものを `h2`〜`h4` に割り当てる。絶対値で決めないのは、PCとSPで同じ見出しでも
  サイズが違うため。
- **リスト** — 短い文字列が同じ左端で等間隔に縦に並んでいれば `<ul>`。
- それ以外は `<p>`。太字の短い行は `<strong>` を付ける。

## 非表示レイヤーも拾う

デザイナーは「開いた状態のハンバーガーメニュー」「タブの裏側」「ホバー時の表示」を
非表示レイヤーとして同じPSDに置いておく。**そこにある文言もページには載る**ので、
原稿としては必要になる。

このスクリプトは非表示グループも読む（読む間だけ表示に切り替え、必ず元に戻すので
**PSDファイル自体は変更しない**）。ただし通常表示のものとは混ぜず、別の塊として出す。

- 羅列版 → `［別状態（PSDで非表示）］` として字下げして続ける
- HTML版 → 黄色い枠の「別状態」ブロックにまとめる

混ぜないのには理由がある。タブの裏側は表示中の要素と**同じ座標に重なっている**ため、
一緒に並べると行や列の判定が壊れて、表がぐちゃぐちゃになる。

## アートボードの有無

アートボードで作られたPSDと、1枚のキャンバスに直接組まれたPSDのどちらも扱える。

| 判定 | 条件 |
|---|---|
| `detect: artboard` | アートボードがある → それぞれを1画面として扱う |
| `detect: group` | 最上位グループ名がPC/SPを示している → 横並びの2カンプとみなす |
| `detect: canvas` | どちらでもない → キャンバス全体を1画面とする |

`detect: canvas` と出たときは画面の切り分けが推測になっている。セクション分けが
妥当か、出力を一度目で確かめる。

## つまずきやすいところ

- **同じ文言が2つ出てきたら、ホバー用の重なり。** 同じ座標に色違いで重ねる作りが
  普通なので、近い位置の同一文言はまとめている。それでも残る場合は、座標が大きく
  離れた別物（実際に2箇所に書かれている）と考えてよい。
- **改行はPSDの改行がそのまま入る。** カンプの見た目を優先した改行が含まれるので、
  原稿として渡す前に意図した改行かを確認する。
- **文字が画像化されている箇所は取れない。** ロゴやバナーの中の文字はテキスト
  レイヤーではないため出てこない。件数が明らかに少ないときはこれを疑う。
